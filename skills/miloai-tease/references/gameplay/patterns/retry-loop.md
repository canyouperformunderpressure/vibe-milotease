# Retry loop

## Design profile

- **Role:** Modifier pattern
- **Best for:** mastery, escalating frustration, playful punishment, learning through failure
- **Typical scale:** scene / phase
- **Can lead a phase:** Usually no
- **Player mainly:** attempts a challenge, reports or triggers failure, receives feedback, then repeats with the same or altered conditions
- **Combines well with:** `timed-challenge.md`, `race.md`, `self-control-challenge.md`, `dual-task-challenge.md`

A retry loop turns failure into more gameplay instead of an immediate terminal branch.

Use it when repeating the task is itself interesting. A retry should normally change something: feedback, pressure, handicap, rule, reward, or narrative context. Do not create an unbounded loop with no way to succeed, surrender, or leave.
